# Rule Explanation — Design Spec

**Workitem:** WI-20260516-ruleExplanation

## Goal

Replace the opaque `rule_triggered` code (e.g. `DD_0_5`) in the HeroCard subtitle with the human-readable `explanation` field that is already returned by the API.

## Context

`RecommendationResult` has two relevant fields:

| Field | Example value | Currently displayed? |
|---|---|---|
| `rule_triggered` | `DD_0_5` | Yes — inline in HeroCard subtitle |
| `explanation` | `Market is 8.2% below its 12-month high.` | No |

The `explanation` field was designed to describe why the rule fired. It is generated by `calculate_recommendation()` in `backend/app/services/recommendation.py` and persisted alongside `rule_triggered` in the `Recommendation` table.

## Change

**File:** `frontend/src/components/HeroCard.tsx`

Replace `{result.rule_triggered}` with `{result.explanation}` in the subtitle paragraph (line ~99 today).

Before:
```
+€120 vs base · 1.2× · −8.2% drawdown · DD_0_5
```

After:
```
+€120 vs base · 1.2× · −8.2% drawdown · Market is 8.2% below its 12-month high.
```

## Scope

- **In scope:** HeroCard subtitle line only.
- **Out of scope:** Backend schema, `rule_triggered` field removal, history page, store, API.

`rule_triggered` remains in the API payload and database — it is an internal engine identifier used for data analysis. It simply stops being rendered.

## Architecture

No new props, no new state, no new API calls. `result.explanation` is already available inside the `RecommendationResult` object passed to HeroCard. This is a single-character diff in the template.

## Testing

- Update any existing test that asserts on `DD_0_5` (or other `DD_*` codes) visible text — assert on the explanation string instead.
- Add one test: when `result` is present, the explanation text is visible in the document.

## Acceptance Criteria

- AC-001: HeroCard subtitle shows `result.explanation` where `result.rule_triggered` used to appear.
- AC-002: The raw code `DD_0_5` (and other `DD_*` codes) is no longer visible in the rendered card.
- AC-003: All existing frontend tests pass (with updated text assertions where needed).
